# Швидкий старт

Встановити бібліотеку, відкрити сесію, поставити реєстру три справжні запитання і коректно закрити
сесію. Спершу програма, далі — розбір кожного її рядка.

## Встановлення

```bash
composer require epptools/sdk
```

Або напряму з GitHub, із прив'язкою до тегу релізу, якщо не хочете залежати від Packagist:

```bash
composer config repositories.epptools vcs https://github.com/epptools/php-sdk
composer require epptools/sdk:^1.0
```

Зовсім без Composer: клонуйте репозиторій і виконайте
`require __DIR__ . '/php-sdk/autoload.php';`. Це реєструє мінімальний автозавантажувач PSR-4 для
простору імен `EppTools\`.

## Що потрібно, перш ніж запускати

| Що | Звідки береться |
|---|---|
| Хост і порт | Ваш обліковий запис. Порт — `700`, якщо вам не сказали інакше. |
| Ваш clID | Ваш ідентифікатор реєстратора, напр. `EXAMPLE`. |
| Пароль | Видається з обліковим записом, змінюється через `login()` — див. [Сесія](session.md). |
| Сертифікат CA реєстру | Порт 700 подає сертифікат від власного приватного CA реєстру. Запитайте в реєстрі набір `.pem`. |
| Адреса відправлення у списку дозволених | Публічна IP-адреса вашого сервера має бути зареєстрована для цього clID, інакше вхід відхиляється з 2200. |

## Уся програма

Збережіть її як `epp-first-run.php`, підставте чотири значення на початку і запустіть командою
`php epp-first-run.php`.

```php
<?php

declare(strict_types=1);

require __DIR__ . '/vendor/autoload.php';

use EppTools\Client;
use EppTools\Config;
use EppTools\Exception\EppException;

$config = Config::fromArray([
    'host'     => 'epp.registry.example',
    'clid'     => 'EXAMPLE',
    'password' => 'your-secret',
    'lang'     => 'en',                          // мова повідомлень про результат, якщо привітання її перелічує
    // 'caFile' => '/etc/epp/registry-ca.pem',   // лише для сертифіката від приватного CA або самопідписаного
]);

$client = new Client($config);

try {
    $greeting = $client->connect();
    echo 'server: ' . ($greeting->value('svID') ?? 'unnamed') . "\n";

    $login = $client->login();
    foreach ($login->securityEvents() as $event) {
        fwrite(STDERR, sprintf(
            "login %s (%s): %s\n",
            $event['level'] ?? 'warning',
            $event['type'] ?? 'custom',
            $event['text']
        ));
    }

    $check = $client->domain()->check(['example.com.ua'], fee: ['create' => 1]);

    if ($check->isAvailable('example.com.ua') === true) {
        echo "example.com.ua is available\n";
        echo '  create, 1 year: ' . ($check->feeFor('example.com.ua', 'create', 1) ?? 'not quoted')
            . ' ' . ($check->fees()['_currency'] ?? '') . "\n";
    } else {
        echo 'example.com.ua is taken: '
            . ($check->unavailableReason('example.com.ua') ?? 'no reason given') . "\n";

        $info = $client->domain()->info('example.com.ua');
        echo '  sponsor: ' . ($info->sponsor() ?? '-') . "\n";
        echo '  expires: ' . ($info->expiryDate() ?? '-') . "\n";
        echo '  status:  ' . implode(', ', $info->statuses() ?: ['-']) . "\n";
        echo '  ns:      ' . implode(', ', $info->nameservers() ?: ['-']) . "\n";
    }

    $balance = $client->balance();
    echo 'available credit: ' . ($balance->availableCredit() ?? '-') . "\n";

    $client->logout();
} catch (EppException $e) {
    fwrite(STDERR, 'EPP error: ' . $e->getMessage() . "\n");
    exit(1);
} finally {
    $client->disconnect();
}
```

Очікуваний вивід на живому обліковому записі, коли ім'я зареєстроване кимось іншим:

```
server: Registry EPP Server
example.com.ua is taken: In use
  sponsor: ACME
  expires: 2027-04-01T09:15:00Z
  status:  ok
  ns:      ns1.example.com.ua, ns2.example.com.ua
available credit: 12500.00
```

Ніщо в цій програмі нічого не змінює і нічого не коштує. `check`, `info` та запит балансу — усі
лише читають, і саме тому вони правильні як перші команди: тільки їх безпечно повторювати наосліп.

## Рядок за рядком

### `require __DIR__ . '/vendor/autoload.php';`

Автозавантажувач Composer. Без Composer підключіть натомість власний `autoload.php` цього SDK.

### `Config::fromArray([...])`

Налаштування підключення. `fromArray()` приймає ті самі імена, що й конструктор, і заповнює кожне
значення за замовчуванням, тож для старту досить короткого масиву:

- **`host`**, **`clid`** та **`password`** не мають корисних значень за замовчуванням. Порожній
  `host` спричиняє `ConfigException` з `connect()`; порожній `clid` чи `password` — з `login()`, ще
  до того, як байт потрапить у канал передачі.
- **`caFile`** тут обов'язковий. Точка підключення на порті 700 подає сертифікат, виданий власним
  приватним CA реєстру, якого немає в жодному системному сховищі довіри, тож із перевіркою вузла,
  залишеною у правильному стані за замовчуванням, рукостискання без нього не вдасться.
- **`port`** за замовчуванням `700`. `lang` за замовчуванням `en`. Усе інше розібрано поле за полем
  у [Сесії](session.md).

Не тримайте пароль у файлі. Читайте його зі змінних середовища або зі свого сховища секретів; у
прикладі він виписаний лише для того, щоб програма була повною.

### `new Client($config)`

Створення клієнта нічого не відкриває. Ви отримуєте об'єкт; сокет буде далі. Другий необов'язковий
аргумент приймає власний транспорт, а третій — логер PSR-3, див. [Сесія](session.md).

### `$greeting = $client->connect();`

Відкриває TLS-сокет і читає незапитане `<greeting>` сервера — перше, що надсилає сервер EPP
(RFC 5730). Привітання перелічує простори імен об'єктів і розширень, які підтримує цей сервер, а
`login()` повертає їх назад, тож сесію ніколи не відхилять за оголошення сервісу, якого сервер не
пропонує.

`connect()` повертає привітання як [`Response`](responses.md). `$greeting->value('svID')` читає з
нього ім'я сервера. Якщо перший кадр не є привітанням, `connect()` спричиняє `ConnectionException`,
а не приймає те, що надійшло, за перелік сервісів.

### `$login = $client->login();`

Надсилає `<login>` з вашим clID і паролем, версією протоколу, мовою та переліком сервісів, узятим із
привітання. Повертає відповідь на вхід.

### Цикл `securityEvents()`

Там, де сервер пропонує розширення безпеки входу (RFC 8807), вхід несе невеликий блок, що
ідентифікує цього клієнта, а сервер відповідає всім, що радить виправити в цій сесії: клієнтський
сертифікат, який добігає кінця, застаріла версія TLS, набір шифрів, який не є AEAD.

На здоровій сесії перелік порожній, тож ставтеся до будь-якого запису як до того, на що треба
зреагувати. Кожен запис завжди несе `text`; `type` і `level` присутні, коли сервер їх надіслав —
звідси значення за замовчуванням через `??`. Найчастіша подія — сертифікат, що спливає протягом
наступних 30 днів; альтернатива тому, щоб дізнатися про це тут, — дізнатися вранці, коли входи
припиняться.

### `$client->domain()->check(['example.com.ua'], fee: ['create' => 1])`

`domain()` повертає обробник доменних команд; `check()` надсилає `domain:check` (RFC 5731) і
повертає відповідь. Іменований аргумент `fee:` додає до неї запит ціни за RFC 8748, тож одне коло
обміну відповідає і на «чи вільне», і на «скільки коштувало б».

Запит ціни безплатний і нічого не змінює. Повну форму таблиці цін, а також те, як перетворити те
саме розширення на **обмеження** суми, яку може списати змінна операція, див. у
[Балансі](balance.md).

### `$check->isAvailable('example.com.ua')`

Повертає `true`, `false` або `null`, коли відповідь про це ім'я нічого не сказала. Саме в трьох
варіантах і суть: звернення до масиву доступності за ключем, який ви написали з помилкою, теж дає
«не знайдено», а ці дві відповіді не мають виглядати однаково в рядку перед реєстрацією.

Порівняння не залежить від регістру, тож ім'я, набране в мішаному регістрі, все одно збігається.

### `$check->feeFor('example.com.ua', 'create', 1)`

Наведена ціна однієї операції за один період, як точний десятковий **рядок**, або `null`, коли
відповідь не несла такої ціни. Ніколи не приводьте його до `float` перед обчисленнями —
користуйтеся `bcmath` або цілими в дрібних одиницях. `fees()['_currency']` — валюта, у якій наведено
всю відповідь.

Суми в цьому посібнику наведено для прикладу, це не тариф реєстру.

### `$check->unavailableReason('example.com.ua')`

Власне формулювання реєстру про те, чому ім'я недоступне — `In use`, `Reserved` — або `null`, коли
воно доступне чи коли реєстр не назвав причини.

### `$client->domain()->info('example.com.ua')`

`domain:info` повертає повний запис імені, яке вам дозволено бачити. Програма надсилає його лише в
гілці, де ім'я зайняте: `info` для неіснуючого імені відхиляється з 2303, і це надходить як
`ObjectDoesNotExistException`.

`sponsor()`, `expiryDate()`, `statuses()` та `nameservers()` — іменовані аксесори, тож ви ніколи не
звертаєтесь до масиву за рядком, який довелося вгадувати. `expiryDate()` повертає власний рядок
реєстру рівно таким, яким його надіслали. Кожен аксесор перелічено у [Відповідях](responses.md).

`nameservers()` охоплює обидві моделі делегування EPP — посилання на об'єкт хоста або ім'я з
вбудованими glue-адресами — тож перелік правильний, хоч би яку з них використовував цей реєстр.

### `$client->balance()`

Баланс облікового запису реєстратора через розширення балансу реєстру. `availableCredit()` — те, що
ви ще можете витратити: баланс плюс будь-яка кредитна лінія, знову ж таки як точний десятковий
рядок. Див. [Баланс](balance.md).

### `$client->logout();`

Завершує сесію. Сервер відповідає 1500 і закриває з'єднання. Сесія, обірвана без виходу, все одно
рахується у вашому обмеженні одночасних сесій, доки не спрацює тайм-аут, тож виходьте дорогою повз.

### `catch (EppException $e)`

Кожен збій, який спричиняє ця бібліотека, розширює `EppException`, тож один catch охоплює все:
поганий аргумент, збій TLS, відмову реєстру. Ловіть підкласи там, де відрізняється правильний
наступний крок: 2104 означає зупинити пакет і поповнити рахунок, 2302 — обрати інше ім'я. Повна
таксономія — у [Помилках](errors.md).

### `finally { $client->disconnect(); }`

Закриває сокет за будь-яких обставин, зокрема на шляхах, де до `logout()` так і не дійшло.

ідентичний, і нічого не тарифікується.
