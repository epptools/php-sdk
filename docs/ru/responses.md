# Ответы

Каждая команда возвращает `EppTools\Response`. Он оборачивает разобранный ответ и отвечает на
вопросы о нём через именованные аксессоры, поэтому вам никогда не приходится лезть в массив по
строке, которую пришлось угадывать.

Эта страница перечисляет **все** аксессоры, сгруппированные по тому, на какой вопрос они отвечают, с
сигнатурой и с тем, что они отдают, когда ответ ничего не несёт.

Два правила, действующие для всего класса:

- **Даты возвращаются собственной строкой реестра** — `2027-04-01T09:15:00Z` или со смещением — и
  никогда как `DateTime`. Календарный день, на который придётся продление, определяет реестр, а
  переформатирование через местный часовой пояс — это ровно тот путь, которым клиент начинает
  показывать вчерашний день и продлевать по нему.
- **Деньги возвращаются точной десятичной строкой**, а не числом с плавающей точкой. `0.1 + 0.2` в
  двоичной плавающей точке не равно `0.3`, и баланс, просуммированный так, уплывает. Используйте
  `bcmath` или целые копейки.

Аксессор, у которого спросили о том, чего в ответе нет, отвечает `null`, `[]`, `false` или `0` — как
позволяет его сигнатура. Это законный ответ — «реестр об этом ничего не сказал», — а не ошибка.

## Результат и исход

| Аксессор | Что возвращает | Когда ответ ничего не несёт |
|---|---|---|
| `code(): int` | Код ответа EPP: 1000, 1001, 2303 … | `0` для приветствия и для любого кадра без `<result>` |
| `isSuccess(): bool` | `true` для любого кода 1xxx | `false` |
| `isPending(): bool` | `true` только для 1001 — принято, завершается офлайн | `false` |
| `isGreeting(): bool` | `true`, когда кадр — это `<greeting>`, а не `<response>` | `false` |
| `message(): ?string` | `<msg>` результата, на языке сессии | `null` |
| `messageLang(): ?string` | Язык этого сообщения: `en`, `uk`, `ua`, `ru` | `null` |
| `errorReasons(): array` | Текст `<extValue><reason>` от неудавшейся команды, как `string[]` | `[]` |
| `extValues(): array` | Блоки `<extValue>` целиком — см. ниже | `[]` |
| `clTRID(): ?string` | Клиентский идентификатор транзакции, который отразил сервер | `null` |
| `svTRID(): ?string` | Идентификатор транзакции реестра. Сохраняйте его рядом с объектом | `null` |

`isSuccess()`, равный true, — это не то же самое, что выполненная работа: 1001 — код успеха, и он
означает, что реестр принял команду и завершит её офлайн. Проверяйте `isPending()`, прежде чем
записывать что-либо как выполненное.

### `extValues(): array`

Если `errorReasons()` даёт словесное объяснение, то этот метод даёт **элемент**, к которому у
сервера претензия, — а это как раз то, с чем можно что-то сделать. Проверка пяти доменов, упавшая на
одном, несёт здесь это одно имя.

```php
foreach ($response->extValues() as $ext) {
    $ext['element'];    // 'name'  — локальное имя проблемного узла, '' если сервер его не назвал
    $ext['namespace'];  // 'urn:ietf:params:xml:ns:domain-1.0'
    $ext['text'];       // 'bad..name' — СОБСТВЕННЫЕ символьные данные узла
    $ext['values'];     // потомки по локальному имени, когда узел является контейнером
    $ext['xml'];        // узел, сериализованный для журнала
    $ext['reason'];     // объяснение сервера
    $ext['lang'];       // его язык
}
```

`text` — это собственные символьные данные элемента, а не рекурсивный `textContent`, поэтому
контейнер никогда не возвращается своими потомками, сплавленными в одну строку, которая читается как
значение, но им не является. `CommandException::subject()` читает первый непустой `text` за вас —
см. [Ошибки](errors.md).

## Идентичность объекта

Эти отвечают одинаково для домена, хоста и контакта.

| Аксессор | Что возвращает | Когда ответ ничего не несёт |
|---|---|---|
| `objectName(): ?string` | Имя домена, имя хоста или **идентификатор** контакта | `null` |
| `roid(): ?string` | Собственный идентификатор объекта в реестре | `null` |
| `sponsor(): ?string` | `clID` — регистратор, которому объект принадлежит сейчас | `null` |
| `registrarOfRecord(): ?string` | Идентификатор, который WHOIS и RDAP реестра публикуют как регистратора | `null` |
| `createdBy(): ?string` | `crID` — регистратор, создавший объект | `null` |
| `createdDate(): ?string` | `crDate`, в том виде, в каком его записал реестр | `null` |
| `updatedBy(): ?string` | `upID` — регистратор, изменивший объект последним | `null`, в том числе когда объект никогда не изменялся |
| `updatedDate(): ?string` | `upDate` | `null`, когда изменений не было |
| `authInfo(): ?string` | Код трансфера из `<authInfo><pw>` | `null`, когда реестр его не выдал |
| `statuses(): array` | Значения статусов из атрибута `s`: `['ok']`, `['clientHold', …]` | `[]` |

`objectName()` читает прямого потомка блока объекта. Для контакта это важно: поиск элемента `<name>`
по всему документу первым найдёт полное имя человека внутри почтового адреса, а подстановка
найденного обратно в качестве идентификатора получит 2303.

Для реселлера `registrarOfRecord()` и `sponsor()` — не одна и та же сторона. `sponsor()` называет
учётную запись, которой объект принадлежит в вашей собственной иерархии; `registrarOfRecord()` —
того, кого публикует реестр.

`updatedBy()` отправляется только регистратору-владельцу. Сверяясь, читайте его в паре с
`updatedDate()`: изменение, которого вы не делали, пришло со стороны реестра или от действия
поддержки, а не из вашей системы.

`authInfo()` — это действующие учётные данные: секрет, позволяющий любому регистратору забрать у вас
домен. Никогда не пишите его в журнал, никогда не вкладывайте в обращение в поддержку и меняйте его
после того, как передали клиенту.

## Домен
| Аксессор | Что возвращает | Когда ответ ничего не несёт |
|---|---|---|
| `expiryDate(): ?string` | `exDate` ровно в том виде, в каком его записал реестр | `null` |
| `registrant(): ?string` | Идентификатор регистранта | `null` |
| `contacts(): array` | Контакты по ролям: `['admin' => ['c-1'], 'tech' => ['c-1','c-2']]`. Регистрант **не** включён | `[]` |
| `contactsFor(string $role): array` | Идентификаторы в одной роли; роль сопоставляется без учёта регистра | `[]` — законный ответ, ведь обязателен везде только регистрант |
| `adminContacts(): array` | `contactsFor('admin')` | `[]` |
| `techContacts(): array` | `contactsFor('tech')` | `[]` |
| `billingContacts(): array` | `contactsFor('billing')` | `[]` |
| `allContacts(): array` | Все идентификаторы в любом качестве, включая регистранта, без повторов | `[]` |
| `nameservers(): array` | Делегирование, в нижнем регистре, в порядке реестра | `[]` |
| `nameserverAddresses(): array` | Встроенные glue-адреса с ключом по имени сервера имён | `[]` |
| `subordinateHosts(): array` | Объекты хостов, живущие **под** этим доменом, в нижнем регистре | `[]` |
| `transfer(): ?array` | Трансфер целиком — см. ниже | `null` |
| `transferStatus(): ?string` | `trStatus`: `pending`, `serverApproved`, … | `null` |
| `transferDate(): ?string` | `trDate` — когда объект в последний раз сменил владельца | `null`, если не менял ни разу |
| `license(): ?string` | Номер товарного знака или лицензии из собственного расширения реестра | `null` |
| `rgpStatus(): array` | Значения статуса RGP, например `['redemptionPeriod']` (RFC 3915) | `[]` |
| `dsRecords(): array` | DS-записи DNSSEC (RFC 5910) | `[]`, когда домен не подписан |
| `keyRecords(): array` | Открытые ключи DNSSEC | `[]` |
| `isSigned(): bool` | Несёт ли домен хоть какие-то данные DNSSEC | `false` |
| `prices(): array` | Подсказки о цене из собственного расширения цен реестра, с ключом по операции | `[]` |
| `priceChannel(): ?string` | Ценовой канал, по которому тарифицируется этот домен | `null` |

`contactsFor()` сопоставляет роль без учёта регистра, потому что реестры непоследовательны в `tech`
против `Tech`, а регистрозависимый поиск молча сообщает «технического контакта нет» о домене, у
которого он есть.

`allContacts()` нужен тогда, когда важен **сам факт** ссылки на контакт, а не роль: перед удалением
контакта или когда вы выясняете, какие из ваших контактных объектов ещё используются.

`nameservers()` покрывает обе модели делегирования EPP: `<domain:hostObj>` — ссылку на объект
хоста — и `<domain:hostAttr>` — имя, встроенное вместе с glue-адресами. Клиент, который читает только
одну из них, получит от реестра, использующего другую, пустой список и сделает вывод, что серверов
имён у домена нет вовсе.

`nameserverAddresses()` возвращает только встроенные glue-адреса:

```php
$info->nameserverAddresses();
// ['ns1.example.com.ua' => [['ip' => '192.0.2.1', 'version' => 'v4']]]
```

Он заполняется только там, где реестр отвечает через `hostAttr`. От реестра, отвечающего через
`hostObj`, вы получите `[]` и будете добирать адреса вызовом `host()->info()` на каждое имя, —
поэтому пустой результат здесь **не** означает, что домен не делегирован. За списком идите в
`nameservers()`.

`subordinateHosts()` важен перед удалением: реестр отказывается удалять домен, пока под ним живут
объекты серверов имён. Проверьте список, удалите их или перенаправьте, а затем удаляйте домен.

`prices()` и `priceChannel()` — это собственные подсказки реестра о цене в `domain:info`, отличные от
котировок RFC 8748 в [`fees()`](#check-и-деньги):

```php
$info->prices();
// ['renewal' => ['value' => '180.00', 'currency' => 'UAH'], …]
$info->priceChannel();
// непрозрачный идентификатор, соответствующий строке опубликованного каталога реестра
```

Домен, зарегистрированный давно, может стоять на другом канале, чем тот, по которому пошла бы новая
регистрация в той же зоне, — поэтому канал задаётся на домен, а не на зону.

### `transfer(): ?array`

Всё уведомление о трансфере — из ответа на transfer или из `trnData` сообщения poll:

```php
$t = $response->transfer();
// [
//   'status'       => 'pending',
//   'requestedBy'  => 'ACME',            // reID
//   'requestedAt'  => '2026-08-14T10:00:00Z',// reDate
//   'actingClient' => 'EXAMPLE',            // acID — кто должен ответить
//   'actBy'        => '2026-08-19T10:00:00Z',// acDate — крайний срок
//   'expiryDate'   => '2028-04-01T09:15:00Z',// exDate, который даст трансфер
// ]
```

Один `transferStatus()` говорит, что трансфер в ожидании, но не говорит, чей он и сколько у вас
времени. `actBy` — момент, после которого реестр решает за вас.

### Записи DNSSEC

```php
$info->dsRecords();
// [['keyTag' => 12345, 'alg' => 8, 'digestType' => 2, 'digest' => 'ABCD…']]

$info->keyRecords();
// [['flags' => 257, 'protocol' => 3, 'alg' => 8, 'pubKey' => 'AwEAAb…']]

$info->isSigned();   // true, когда непуст хотя бы один из списков
```

## Хост

| Аксессор | Что возвращает | Когда ответ ничего не несёт |
|---|---|---|
| `hostAddresses(): array` | Glue-адреса самого объекта хоста: `[['ip' => '192.0.2.1', 'version' => 'v4'], …]` | `[]` |

Glue-адреса несёт только хост **внутри** зоны, которую он обслуживает. Для внешнего сервера имён
реестр не возвращает ни одного, и это норма, а не пропущенный ответ.

Список ограничен самим объектом хоста, поэтому в него никогда не примешиваются пер-именные
glue-адреса встроенного делегирования домена — для них есть `nameserverAddresses()`. Отсутствующий
атрибут `ip` означает `v4` — это собственное значение по умолчанию схемы хоста, — так что реестр,
работающий только с IPv4 и опускающий атрибут, отражается верно, а не как что-то другое.

## Контакт

| Аксессор | Что возвращает | Когда ответ ничего не несёт |
|---|---|---|
| `postalInfo(): array` | Адреса с ключом по форме: `'int'` (ASCII) и `'loc'` (локальная письменность) | `[]` |
| `email(): ?string` | Адрес электронной почты контакта | `null` |
| `voice(): ?string` | Телефонный номер в форме EPP `+CC.NNNN` | `null` |
| `fax(): ?string` | Номер факса, та же форма | `null` |
| `disclose(): ?array` | Предпочтение раскрытия | `null`, когда контакт его не несёт и действует одна лишь политика реестра |

```php
$c = $client->contact()->info('C-0001');

$c->postalInfo();
// ['int' => ['name' => 'ACME LLC', 'org' => 'ACME LLC', 'street' => ['1 Main St'],
//            'city' => 'Kyiv', 'sp' => '', 'pc' => '01001', 'cc' => 'UA'],
//  'loc' => [...]]
```

Контакт может нести любую из форм или обе; части, которых он не несёт, представлены `''`, а не
отсутствуют. Читайте `['int']`, когда нужно то, что можно безопасно напечатать где угодно, и
`['loc']`, когда нужен адрес в том виде, в каком его написал сам регистрант.

```php
$c->disclose();
// ['flag' => false, 'elements' => ['email', 'voice']]
```

`flag`, равный true, означает, что перечисленные элементы **можно** публиковать; false — что их
следует скрывать. Элементы, *не* попавшие в список, получают противоположное флагу обращение,
поэтому без флага список бессмыслен. Элемент, существующий по одному на каждую почтовую форму,
появляется вместе со своим типом — как `name:int` или `addr:loc`.

## Check и деньги
| Аксессор | Что возвращает | Когда ответ ничего не несёт |
|---|---|---|
| `availability(): array` | Вся карта `*:check`: имя или идентификатор ⇒ `bool` | `[]` |
| `isAvailable(string $name): ?bool` | Одно имя, сопоставляется без учёта регистра | `null` — «ответ ничего о нём не сказал» |
| `unavailableReason(string $name): ?string` | Почему имя недоступно: `In use`, `Reserved` | `null`, когда оно свободно или причина не указана |
| `fees(): array` | Котировки RFC 8748 по каждому имени плюс `'_currency'` | `[]` |
| `feeFor(string $name, string $operation, int $years = 1): ?string` | Одна котировка, десятичной строкой | `null`, когда ответ такой котировки не нёс |
| `feeClass(?string $name = null): ?string` | Тарифный класс реестра: `premium`, `standard` | `null` |
| `isPremium(?string $name = null): bool` | Тарифицируется ли имя вне стандартного прайс-листа | `false` |
| `chargedFee(): ?array` | Сколько на самом деле списала изменяющая команда: `['currency' => 'UAH', 'fee' => '100.00']` | `null` |
| `feeAmount(): ?string` | Сумма из `chargedFee()` | `null` |
| `feeCurrency(): ?string` | Валюта из `chargedFee()` | `null` |
| `balance(): ?array` | Весь блок баланса | `null`, когда это не ответ на запрос баланса |
| `creditLimit(): ?string` | Ваша кредитная линия | `null` |
| `currentBalance(): ?string` | Ваш текущий баланс | `null` |
| `availableCredit(): ?string` | То, что вы ещё можете потратить: баланс плюс кредитная линия, если она есть | `null` |

Ради `null` от `isAvailable()` он и существует. Обращение к `availability()` вручную даёт `null` и
для «занято», и для «вы ошиблись в ключе», а эти два ответа не должны выглядеть одинаково в строке
перед регистрацией.

```php
$check = $client->domain()->check(['example.com.ua', 'taken.com.ua']);

$check->availability();                       // ['example.com.ua' => true, 'taken.com.ua' => false]
$check->isAvailable('EXAMPLE.com.ua');        // true
$check->isAvailable('never-asked.com.ua');    // null
$check->unavailableReason('taken.com.ua');    // 'In use'
```

### `fees()` и `feeFor()`

```php
$r = $client->domain()->check(['example.com.ua'], fee: ['create' => [1, 2, 5]], currency: 'UAH');

$r->fees();
// [
//   '_currency'       => 'UAH',
//   'example.com.ua'  => [
//       'avail'    => true,               // false ⇒ читайте 'reason' (зона не обслуживается, валюта…)
//       'reason'   => null,
//       'class'    => 'premium',          // присутствует, только если реестр прислал класс
//       'commands' => ['create' => ['years' => 1, 'fee' => '100.00']],
//       'periods'  => [['op' => 'create', 'years' => 1, 'fee' => '100.00'],
//                      ['op' => 'create', 'years' => 2, 'fee' => '200.00'],
//                      ['op' => 'create', 'years' => 5, 'fee' => '480.00']],
//   ],
// ]

$r->feeFor('example.com.ua', 'create', 5);    // '480.00'
```

Запрос одной операции для нескольких периодов возвращает по котировке на период. В карте `commands`
лежит одна запись на операцию — для первого запрошенного вами периода, — поэтому **если вы спросили
больше одного периода, читайте `feeFor()` или `periods`**. `transfer` и `restore` — операции на один
год, сколько бы лет вы ни запросили, так что читайте их за один год.

Суммы здесь иллюстративны и не являются тарифом реестра. Всё о том, как спрашивать цену и как её
ограничивать, — в [Балансе](balance.md).

### `isPremium()` и `feeClass()`

```php
$r->feeClass('example.com.ua');   // 'premium' | 'standard' | null
$r->isPremium('example.com.ua');  // true, когда класс присутствует и не равен 'standard'
```

Оба принимают необязательное имя; без него они отвечают за первое имя в ответе, у которого класс
есть. `false` от `isPremium()` — не обещание стандартной цены, а лишь то, что ответ не объявил
особого класса. Тарифицируйте по `fees()`, а ограничение суммы ставьте на самой изменяющей команде.

### Сколько списали на самом деле

```php
$create = $client->domain()->create('example.com.ua', ['years' => 1, 'registrant' => 'C-0001']);

$create->chargedFee();    // ['currency' => 'UAH', 'fee' => '100.00'] или null
$create->feeAmount();     // '100.00'
$create->feeCurrency();   // 'UAH'
```

Реестр отражает это в ответе на удавшуюся изменяющую команду, которая несла согласование тарифа.
Записывайте рядом с заказом `feeAmount()`, а не ту цену, которую вы взяли из `check`: между этими
двумя моментами тариф мог измениться.

### Блок баланса

```php
$b = $client->balance();

$b->balance();           // ['creditLimit' => '…', 'balance' => '…', 'availableCredit' => '…']
$b->creditLimit();
$b->currentBalance();    // назван по смыслу, потому что balance() возвращает весь блок
$b->availableCredit();
```

Все три — десятичные строки в валюте вашей учётной записи. См. [Баланс](balance.md).

## Poll

| Аксессор | Что возвращает | Когда ответ ничего не несёт |
|---|---|---|
| `messageId(): ?string` | Идентификатор сообщения в очереди, который передают в `poll()->ack()` | `null` — очередь пуста |
| `messageCount(): int` | Сколько сообщений остаётся в очереди | `0` |
| `queueMessage(): ?string` | Текст **уведомления**, из `<msgQ><msg>` | `null` |
| `queueMessageLang(): ?string` | Язык уведомления: `uk`, `ru`, `en` | `null` |
| `queueDate(): ?string` | Когда уведомление поставлено в очередь | `null` |
| `pendingActionData(): ?array` | Итог операции, которую реестр обработал офлайн | `null` для обычного уведомления и для пустой очереди |

**`queueMessage()`, а не `message()`.** `message()` возвращает шапку результата команды — «Command
completed successfully; ack to dequeue», — а это постоянная строка. Настоящее содержимое уведомления
лежит в `queueMessage()`, и, прочитав не тот метод, вы получаете шапку, тогда как содержимое
выбрасывается, а ack необратимо уничтожает его в реестре.

Уведомление несёт собственный язык, заданный для каждого регистратора отдельно и не зависящий от
языка сессии, о котором сообщает `messageLang()`.

### `pendingActionData(): ?array`

Именно так отложенная команда в итоге отчитывается (RFC 5731 §3.3, RFC 5733 §3.3). Вы отправляете
create, получаете **1001** и `svTRID`; позже вердикт приходит сообщением poll.

```php
$pan = $notice->pendingActionData();
// [
//   'object'  => 'example.com.ua',
//   'success' => true,                        // атрибут paResult
//   'clTRID'  => 'PHP-SDK-…-0007',            // из paTRID: ИСХОДНАЯ команда
//   'svTRID'  => 'SRV-…-00042',
//   'date'    => '2026-08-14T10:05:00Z',      // paDate: когда действие завершилось
// ]
```

- **Только `success` говорит, сработало ли.** Окружающий `<result code="1301">` означает «вот
  сообщение», а не «ваша операция удалась». Читать вместо этого его — классическая ошибка: тогда
  каждый ответ poll выглядит успехом. Отсутствующий вердикт считается неудачей, потому что
  отсутствующий вердикт — это не «да».
- **`svTRID` сопоставляет вердикт** с той командой, на которую вы получили 1001. Не считайте, что
  это самая последняя команда; poll — это очередь.
- **`date`** — это когда завершилось действие, а не когда вы опрашивали очередь.

Блок сопоставляется по локальному имени во всех объектных пространствах имён, поэтому возвращаются
и `domain:panData`, и `contact:panData`.

## Сессия и безопасность

| Аксессор | Что возвращает | Когда ответ ничего не несёт |
|---|---|---|
| `securityEvents(): array` | События безопасности входа RFC 8807 об этой сессии | `[]` — здоровая сессия |
| `serviceObjUris(): array` | Приветствие: объектные сервисы, которые объявляет сервер | `[]` |
| `serviceExtUris(): array` | Приветствие: сервисы расширений, которые он объявляет | `[]` |

```php
foreach ($client->login()->securityEvents() as $event) {
    $event['text'];              // всегда присутствует
    $event['type']   ?? null;    // certificate | cipher | tlsProtocol | password | newPW | stat | custom
    $event['level']  ?? null;    // 'warning' | 'error'
    $event['exDate'] ?? null;    // дата истечения сертификата, для type=certificate
}
```

Сервер возвращает их только клиенту, который участвовал в расширении. Подробный разбор — в
[Сессии](session.md#безопасность-входа-rfc-8807).

## Прямой доступ
Для всего, что именованные аксессоры не моделируют: для собственного расширения, для поля, которое
добавит будущий сервер.

| Аксессор | Что возвращает | Когда ответ ничего не несёт |
|---|---|---|
| `value(string $localName): ?string` | Первый где-либо встреченный элемент с таким локальным именем, обрезанный по краям, в любом пространстве имён | `null` |
| `values(string $localName): array` | Все элементы с таким локальным именем, обрезанные по краям | `[]` |
| `resData(): ?\DOMElement` | Элемент `<resData>` — для собственного разбора | `null` |
| `raw(): string` | XML ответа ровно в том виде, в каком он пришёл | тот пустой документ, который вам передали |
| `dom(): \DOMDocument` | Разобранный документ | — |
| `xpath(): \DOMXPath` | Объект XPath с уже зарегистрированными префиксами | — |
| `Response::fromXml(string $xml): self` | Разбирает кадр в `Response`. При некорректном XML выбрасывает `ConnectionException` | — |

`value()` и `values()` сопоставляют **локальное** имя, игнорируя пространство имён, — именно это
делает их полезными против расширения, которое вы не моделировали. Две ловушки, о которых стоит
сказать:

- Статус живёт в **атрибуте** `s`, поэтому `values('status')` вернёт ряд пустых строк. Используйте
  `statuses()`.
- `ns` — это лишь обёртка вокруг делегирования, поэтому `values('ns')` вернёт одну сплавленную
  строку. Используйте `nameservers()` или `values('hostObj')`.

В `xpath()` уже привязаны такие префиксы: `e` (базовый EPP), `domain`, `contact`, `host`, `secDNS`,
`rgp` и `fee` — пространства имён из RFC, одинаковые у любого реестра.

Для собственного расширения вашего реестра префикс не привязан: его URI неизвестен, пока не прочитано
приветствие. И он не нужен: все аксессоры на этой странице находят данные расширения по ЛОКАЛЬНОМУ
ИМЕНИ, поэтому лицензия или цена читаются одинаково, в каком бы пространстве имён они ни пришли. Если
всё же нужен запрос вручную, привяжите префикс сами — к тому, что определил клиент:

```php
$xpath = $response->xpath();
$xpath->registerNamespace('reg', $client->registryExtUri());
$xpath->query('//reg:license');
```

```php
$nodes = $response->xpath()->query('//domain:hostAttr/domain:hostName');
foreach ($nodes as $node) {
    echo $node->textContent, "\n";
}
```

`raw()` — это незамаскированный кадр. Если вы его храните, маскируйте `<pw>`, `<newPW>` и
`<authInfo>` сами: библиотека маскирует их в собственном журнале по той же причине.

`Response::fromXml()` — то, чем библиотека строит каждый ответ, и он объявлен публичным, чтобы вы
могли разобрать перехваченный вами кадр. Некорректный XML выбрасывает `ConnectionException`, а не
возвращает недостроенный объект.
